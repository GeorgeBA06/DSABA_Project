# Приёмка frontend ↔ backend (реальный запуск)

Статус: **план проверок; пока не выполнен с PostgreSQL**. Тестируйте на отдельной пустой БД. Не используйте существующие рабочие данные.

1. Backend: настройте `.env`, RSA-ключи, PostgreSQL; выполните `mvn clean verify`, `docker compose up -d postgres`, `mvn spring-boot:run`. Проверьте `health` и успешное применение Flyway V1.
2. Frontend: выполните `npm install`, `npm run check`, `npm run build`, `npm run test:offline`, `npm run dev`.
3. Запустите `tools/live-smoke.mjs` с учётными данными bootstrap admin. Сохраните HTTP-ошибки и лог приложения. Скрипт создаёт тестовые записи.
4. Браузер (desktop и tablet): проверьте вход администратора, специалиста, руководителя, выход, refresh/access-токены, смену пароля; недоступные действия скрыты, прямой URL без роли даёт отказ, backend возвращает 403.
5. Поставщики/каталог: создание, редактирование, ассортимент, заявка на активацию, независимое решение, выбор только доступного товара в заказе.
6. Договор: черновик, отправка, отклонение и новая версия, утверждение и прекращение.
7. Заказ: создание из двух позиций, редактирование черновика, отказ и переработка, утверждение, увеличение, перенос срока, независимое согласование; проверка сохранённого срока для рейтинга.
8. Поставки: частичное поступление, подтверждение, частичная приёмка, контроль суммарного количества, повторная приёмка остатка, брак, возврат и утверждение.
9. Исправления: попытка исправить поступление со связанной приёмкой должна дать контролируемый отказ; исправление приёмки без возвратов должно пройти согласование; старые факты остаются в истории.
10. Претензия: создание по строке заказа, отправка, начало урегулирования, закрытие полностью; закрытие частично допускается только независимым руководителем.
11. Рейтинги: предварительный/без данных, утверждённая экспертная оценка, публикация при наличии не менее 3 подходящих заказов и всех критериев, история предыдущих результатов, выгрузка отчёта XLSX.
12. Администратор: создание, назначение и отзыв роли, блокировка/разблокировка, сброс пароля, проверка аудита и того, что блокировка отзывает сессии.
13. Негативные тесты: 400/401/403/404/409, недоступный сервер, пустые справочники, более 100 элементов выбора, повторная отправка форм, конкурирующая приёмка, старые версии документов.
14. При обнаружении ошибки фиксируйте запрос, HTTP-статус, ответ JSON, путь экрана и логи Spring Boot. Без этих результатов нельзя утверждать, что приложение прошло end-to-end приёмку.
