# Stage 2 — отчёт о совместимости frontend и backend

**Дата:** 31 октября 2026. **База:** frontend Stage 1 + backend Stage 4 с единственной поправкой к DTO строк версий заказа.

## Подтверждено в доступном окружении

- 97/97 HTTP method + path присутствуют в матрице UI-вызовов `docs/API_UI_COVERAGE.json`, которая формируется проверкой исходных маркеров. Это **статическая достижимость**, не execution coverage.
- 16 новых сценариев формируют запросы со схемами, соответствующими OpenAPI; 134 утверждения успешно выполнены, включая проверки обязательных полей и числовых значений.
- 21 автономная проверка реального кода ApiClient прошла: login, авторизация заголовком, refresh, одновременные 401 с одной ротацией refresh, отказ refresh, 403, 204, сетевые ошибки, восстановление после перезагрузки.
- TypeScript semantic проверен с временными локальными React-типами: 0 ошибок. **Это не равно проверке `npm run check` с фактическими npm-пакетами.**
- Backend `tools/run-offline-checks.sh`: 30 таблиц / 30 Entity / 30 JpaRepository, 97 OpenAPI операций, Java compile с заглушками, 16 арифметических проверок, XLSX — PASS.
- Схемы и файлы сторон не расходятся по пути, HTTP-методу и базовым DTO; для переработки заказа добавлены `productId` и `lineNo` в `OrderVersionLineView` и OpenAPI.

## Найденные и устранённые расхождения

1. Ограничение выборов первыми 100 записями в формах заменено серверной пагинацией с защитой от слишком больших списков.
2. Товары заказа выбираются только из предлагаемого выбранным поставщиком ассортимента.
3. Запрещённые переходы статуса поставщика не предлагаются, независимые согласования учитывают авторство.
4. Номенклатуру при переработке отклонённого заказа нельзя менять (как требует `OrderService`).
5. При исправлении поступления идентификатор строки переводится к актуальной версии по устойчивому `segmentKey`.
6. Для возврата проверяется доступное не возвращённое количество; для прочих отклонений при исправлении приёмки требуется причина.
7. Закрытие претензии с частичным или нулевым удовлетворением доступно только независимому руководителю.
8. Смена своего пароля корректно завершает клиентский сеанс даже после немедленного отзыва токена сервером.

## Не подтверждено

- `npm install`, `npm run check`, `npm run build`, запуск UI в реальном браузере.
- Настоящая `mvn clean verify`, Flyway/Hibernate на PostgreSQL, запуск Docker/Testcontainers.
- Запуск подготовленного `tools/live-smoke.mjs` — скрипт требует реально работающего сервера и тестовой БД; синтаксис проверен, **результат не получен**.
- Фактическая корректность всех 97 бизнес-сценариев на реальных данных, включая конкурентность и транзакции. Маршрутное покрытие не доказывает это.

Backend Stage 4 имеет собственные известные ограничения: не все способы расширенного пересмотра заказа поддержаны, пакетные исправления нескольких документов и произвольный as-of рейтинг не реализованы. Frontend не должен обещать функциональность, которой нет в 97 действующих API-операциях.

## Критерий окончательной готовности

Успешные реальная сборка frontend, Maven verify с Testcontainers, запуск на PostgreSQL, live smoke и ручное прохождение чек-листа с ролями, browser/network/console и негативными сценариями. До этого состояние: **контрактно интегрированная кодовая база, нуждается в технической приёмке**.
