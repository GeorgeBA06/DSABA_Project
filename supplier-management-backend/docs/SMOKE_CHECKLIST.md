# Smoke-приёмка на пользовательском компьютере

Выполняйте на **новой пустой базе** и из корня проекта.

1. Проверить `java -version`, `mvn -version`, `docker version`.
2. Генерировать собственную RSA пару (`bash tools/generate-local-keys.sh` или OpenSSL в PowerShell).
3. Поднять БД `docker compose up -d postgres`.
4. Установить переменные из README, включая сильный bootstrap пароль.
5. Запустить `mvn clean verify`. Все unit/JPA/HTTP/Testcontainers тесты должны пройти; при падении сохранить полные логи.
6. Запустить `mvn spring-boot:run` и проверить `GET /actuator/health` -> 200/UP.
7. Выполнить логин администратора -> 200 с access/refresh. Проверить `GET /api/v1/auth/me` -> 200 и роль ADMINISTRATOR.
8. Без токена `GET /api/v1/suppliers` -> 401; admin без закупочной роли не может создавать поставщика -> 403.
9. Через `/api/v1/admin/users` создать специалиста и руководителя. Проверить 403 при попытке специалиста открыть admin-API.
10. Создать категории, единицы и товары; поставщика-кандидата, связать товар, запросить ACTIVE и согласовать от имени другого руководителя.
11. Создать договор и согласовать версию от другого пользователя.
12. Создать заказ с товаром и сроком; отправить и согласовать. Зарегистрировать поступление и частичную приёмку, проверить возвраты и защиту от превышения количества.
13. Создать претензию, записать взаимодействие, сформировать предварительный рейтинг (для одного заказа ожидается PRELIMINARY) и проверить JSON отчёт.
14. Скачать `/api/v1/reports/suppliers.xlsx`; открыть в Excel/LibreOffice. Проверить, что строки и значения совпадают с JSON API.
15. Вызвать `/api/v1/auth/refresh` дважды со старым refresh: первый -> 200, второй -> 401; после этого доступ по токену той же сессии -> 401.
16. Заблокировать, разблокировать, сбросить пароль, проверить отзыв предыдущих сессий и невозможность согласования собственных действий.

**Не принимайте проект по одному health endpoint.** Требуется полный результат Maven/Testcontainers и HTTP smoke; отсутствие подтверждения надо считать открытым техническим риском.
