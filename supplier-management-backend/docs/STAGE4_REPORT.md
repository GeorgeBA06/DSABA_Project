# Stage 4 — HTTP, Security и аудит работоспособности

**Дата:** 31.10.2026. **Статус:** реализация исходников выполнена; полная интеграционная приёмка НЕ завершена.

## Реализовано

- 30 PostgreSQL таблиц, 30 JPA Entity, 30 репозиториев; Flyway V1 не менялась.
- 19 исходных сервисных/политических Java-классов Stage 3; новые сервисы аутентификации, чтения, аналитики и администрирования.
- Spring Security без stateful HTTP-session, без публичной регистрации; BCrypt с cost=12; JWT RS256 с привязкой к сессии; ротация opaque refresh и обнаружение повторного использования, отзыв по logout/блокировке/смене пароля; первый администратор создаётся только при старте.
- Защита закупочных действий от роли-only admin, запрет самосогласования, проверка полномочий в сервисах и для REST чтения.
- 97 HTTP-операций в 83 маршрутах, типизированные запросы/ответы и пагинация (1–100 записей), JSON ошибки без утечки стектрейсов/SQL, OpenAPI JSON.
- Минимальная информационная панель, выгрузка отчёта поставщиков в XLSX (Java ZIP + Office Open XML), лимит 10 000 строк.
- Тесты: JWT подпись/проверка (`JwtTokenTest`), SQL/сущности (`SchemaJpaIT`), сквозные сервисные сценарии (`ServiceWorkflowIT`), HTTP с JWT и PostgreSQL (`ApiSecurityWorkflowIT`).

## Риски, выявленные аудитом

1. **Сервисный Stage 3 не покрывает весь старый расширенный функционал.** Поддерживаются увеличение количества и перенос срока, но не все варианты пересмотра утверждённого заказа; сложные групповые корректировки и arbitrary `as-of` рейтинг также не реализованы. В API отсутствуют кнопки/маршруты для неподдерживаемых операций.
2. **Конкурентность.** Поставки, приёмка и возвраты блокируют родительский заказ, но поведение PostgreSQL при реальной конкурентной нагрузке требуется подтвердить.
3. **Исторические оценки.** Рейтинг считает текущие факты в окне последних 90 дней; старые снимки хранятся, но произвольное восстановление прошлого на основе позднее исправленных событий не реализовано.
4. **Слой хранения.** SQL V1 содержит составные FK и триггеры неизменяемости. Их совместимость с реальным порядком flush Hibernate ещё не подтверждена.
5. **Безопасность и эксплуатация.** Есть временная блокировка после пяти неудачных входов и проверка действующей сессии. Не реализован распределённый rate-limiting для неизвестных логинов, централизованное наблюдение за атаками и автоматическая ротация RSA ключей — это отдельное усиление перед публичным развёртыванием.
6. **Границы производительности.** Реестр отчётности имеет ограничение 10 000 поставщиков. У некоторых справочных запросов ещё нет полнотекстового поиска; рейтинговый отчёт собирается через запросы по поставщикам и оптимален для небольшого объёма курсового проекта, а не миллионов записей.
7. **Управление секретами.** Настоящий приватный RSA ключ генерируется локально и не упакован. Тестовая RSA-пара публична внутри тестовых исходников, поэтому категорически не подходит для эксплуатации.

## Критерии готовности к подключению React

1. `mvn -B clean verify` завершился без ошибок в среде с Docker.
2. `docker compose up -d postgres` + `mvn spring-boot:run` запускают чистую БД, health возвращает UP.
3. На HTTP маршрутах подтверждены: аутентификация, создание сотрудников с ролями, CRUD каталога, статус поставщика, версия договора, заказ, поставка, приёмка, предварительный рейтинг, экспорт XLSX, refresh/logout/replay protection.
4. Ролевые запреты дают 403, unauthenticated запросы 401, а персональные/секретные поля не появляются в JSON.
5. Все дополнительные функции, которые нужны в финальном UI, отмечены либо работающими, либо честно исключёнными из первой версии.

До выполнения этих критериев проект является **подготовленной к запуску реализацией**, не подтверждённым production-продуктом.
