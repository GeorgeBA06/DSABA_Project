# Демонстрационное заполнение SupplierHub

Нужны Python 3.9+ с базой часовых поясов и запущенный backend с PostgreSQL. На Windows при ошибке `ZoneInfoNotFoundError` установите базу командой `python -m pip install tzdata`.

Скрипт вызывает API и создаёт связанные документы с согласованием отдельным руководителем. Все операции отражаются в аудите. Запускайте в локальной или демонстрационной базе.

Из корня репозитория в Linux или macOS выполните:

```bash
python3 tools/seed-demo.py --api http://127.0.0.1:8081/api/v1
```

В PowerShell:

```powershell
./tools/seed-demo.ps1 -ApiUrl http://127.0.0.1:8081/api/v1
```

Введите существующий пароль администратора и новый пароль для двух демонстрационных сотрудников. Скрипт выводит их логины после успешного завершения. Пароль сотрудников должен содержать минимум 12 символов и занимать максимум 72 байта UTF-8.

Для автоматического запуска задайте `DEMO_ADMIN_PASSWORD` и `DEMO_USER_PASSWORD` через переменные окружения. Для другого администратора используйте `--admin-login` или `-AdminLogin`.

## Что показывать в интерфейсе

- Войдите специалистом. В реестре будут три поставщика с меткой `DEMO` и идентификатором набора. У «Нового партнёра» заявка на активацию ожидает решения.
- У «ОфисТехники» три полностью исполненных заказа, подтверждённые поступления и приёмки, утверждённая экспертная оценка и опубликованный рейтинг.
- У «ТехноПоставки» частичная поставка, отклонение по качеству, согласованный возврат и претензия в процессе урегулирования. Рейтинг предварительный.
- В заказах также доступны черновик, версия на согласовании и отклонённая версия для переработки.
- Войдите руководителем для принятия ожидающих решений и работы с рейтингами.
- Откройте отчёт поставщиков и экспортируйте Excel. В административной учётной записи доступны созданные сотрудники и аудит.

## Повторный запуск и остановка

Каждый обычный запуск создаёт отдельный набор с новым идентификатором. Можно задать собственный `--batch presentation1` или `-Batch presentation1`.

Повторное использование идентификатора существующего набора отклоняется до создания новых записей. При сбое уже созданные данные сохраняются. Исправьте причину и используйте новый идентификатор. Запускайте заполнение последовательно, поскольку параллельные запуски с одинаковым идентификатором могут столкнуться с уникальными ограничениями.

Для полного удаления демонстрационных данных используйте отдельную тестовую базу и её обычную процедуру пересоздания. Существующие документы связаны с аудитом и историей согласований.
